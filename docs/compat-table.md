# Сумісність версій (О6.2)

Запланована зміна: додано тарифи `economy`/`comfort`, схема `003_tariffs.sql` розширює
`rides` полями `tariff`, `distance_km`; події отримують `schema_version`. Старий клієнт
не надсилає `tariff`, новий — може надсилати. Рядок — хто надсилає, стовпець — хто
приймає.

| Клієнт \ сервер | N (без тарифів) | N+1 (tariffs_v2, прапорець увімкнено) |
|---|---|---|
| N (збережені запити без `tariff`) | так | **так**: відсутнє поле означає `standard`; тест — `python scripts/replay.py` (`docs/client-v1.json`) |
| N+1 (`tariff: comfort`) | ні: сервер N не знає поля й поверне 409 `feature_disabled` | так |

| Подія \ обробник | N | N+1 |
|---|---|---|
| `ride.requested` / `driver.assigned` v1 (без `schema_version`/`tariff`) | так | **так**: новий обробник читає відсутні поля як замовчування; тест — `tests/test_routes.py::test_gateway_message_has_seq_and_is_not_applied_twice` і події з фікстури |
| Подія з `schema_version: 2` | ні | так |

| WS-повідомлення \ клієнт | N (без `seq`) | N+1 (`seq`) |
|---|---|---|
| v1 (без `seq`) | так | так: `seq = 0`, пропуск заповнюється стрічкою `?after=` |
| v2 (з `seq`) | так: невідоме поле ігнорується | так: позиція оновлюється з WS, дублі відсікаються за `id` |

Висновки щодо порядку оновлення:

1. Спочатку застосовуємо міграцію `003_tariffs.sql` і оновлюємо **obi два** сервери та
   обидва обробники (вони вміють читати старі події). Лише після цього вмикаємо прапорець
   `tariffs_v2` і випускаємо нових клієнтів.
2. Відкат до межі — `enabled: false`: нові запити знову отримують 409 `feature_disabled`,
   а вже створені поїздки зберігають свій тариф. Колонки не видаляємо, дані не знищуємо.
3. Розбір подій v1 в обробникові N+1 лишаємо, доки в Redis Streams не зникнуть старі
   повідомлення (групи `taxi-worker`, `gateway-a`, `gateway-b`).

Збережені запити клієнта N: [client-v1.json](client-v1.json).
